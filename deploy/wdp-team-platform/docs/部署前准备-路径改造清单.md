# 部署前准备 · 路径改造与待办清单

> 更新：2026-07-23。背景：本地开发用 Windows 绝对路径（E:\wdp-team-hermes\...），
> 公网部署跑在 Linux 容器里，路径体系完全不同。本清单梳理"哪些要改、怎么改"。

## 一、路径机制真相（先看这个）

**平台代码本身不写死盘符**——所有路径都从 3 个环境变量派生：

| 环境变量 | 本地值 | K8s 部署值 |
|---|---|---|
| `HERMES_HOME` | `E:\wdp-team-hermes\hermes-home` | `/data/hermes-home`（PVC 挂载） |
| `HERMES_KNOWLEDGE_DIR` | `E:\wdp-team-hermes\knowledge` | `/data/knowledge`（RWX PVC） |
| `HERMES_WEBUI_AGENT_DIR` | `E:\wdp-team-hermes\agent-src` | `/opt/hermes`（镜像内） |

→ **代码层面换环境只要换这 3 个环境变量**（deployment.yaml 里配），不需要改代码。
盘符问题只存在于"数据文件"里（skills/SOUL/脚本），见下。

## 三、部署前必改（数据文件里的绝对路径）

### 3.1 skills 里的绝对路径 → 改为环境变量/相对说法
团队 skills（hermes-home/skills/）里写了本地绝对路径的位置，部署前统一改为：
- 命令示例里 `E:\wdp-team-hermes\xxx` → `$HERMES_HOME/../xxx` 或"工程根目录下的 xxx"
- Python 脚本（如 verify_profile_isolation.py）顶部常量 → `os.getenv('HERMES_HOME')` 派生
- 排查命令：`grep -rn '[A-Z]:\\\\wdp-team\|/[a-z]/wdp-team' hermes-home/skills/`

### 3.2 成员工作库路径（devices.json）——**架构上天然没问题**
个人工作库本体在成员自己的电脑上（如 `C:\Users\xxx\Desktop\...`），服务器只存
索引+路径字符串。部署后 machine_id 互锁会正确判定"服务器 ≠ 成员设备"→ 置灰，
成员在自己电脑上通过浏览器登录时才解锁。**不需要改**，但要在使用说明里写清。

### 3.3 运维脚本（本地专用，不上服务器）
- `scripts/start-team-webui.bat`、`scripts/reset_test_env.py` 写死 E:\ ——它们只在本地用，
  部署不带走。若下次换盘，参照 skill 的"换盘 2 文件必改"配方。
