# WDP 团队 AI 工作台 · 部署说明（给运维）

> 更新：2026-07-23。联系人：马冠杰（产品）。
> 目标：把这套多用户 AI 工作台部署到公网可访问的 K8s 环境，供产品团队使用。

## 一、这是什么

一套自托管的团队 AI 工作台（基于 Hermes Agent + 定制 WebUI）：
- 多用户登录（管理员/成员角色），每人一个独立 AI 助手
- 团队知识库（信号/需求/设计，Markdown + git 版本化）
- 对话产出 → 提交入库 → 管理员审核 → 进团队知识库的闭环

**两个 gitlab 仓库：**

| 仓库 | 地址 | 内容 |
|---|---|---|
| 工作台（本仓库） | http://gitlab.51cloud.local/Maguanjie/wdp-team-platform | Dockerfile、k8s 清单、定制代码 overlay、脚本、文档 |
| 知识库 | http://gitlab.51cloud.local/Maguanjie/wdp-team-knowledge | 团队知识数据（部署时初始化到共享卷，运行期持续写入） |

## 二、架构一图流

```
浏览器（团队成员）
   ↓ HTTPS
Ingress（TLS + sticky session，按 hermes_session cookie 亲和）
   ↓
Service → WebUI Pod ×2（4C8G；镜像 = 官方 web-ui + webui-overlay 定制层 + agent 源码）
   ↓ 挂载
共享卷 PVC（RWX）×2：
   /data/knowledge     ← 团队知识库（git 仓库，与 gitlab 同步）
   /data/hermes-home   ← 运行态（成员 profiles、用户表、配置）
```

## 二·五、工作台 ↔ 知识库 如何互相作用（重点，先看懂再部署）

**三层关系，工作台从不直连 gitlab：**

```
GitLab(wdp-team-knowledge)  ←── git push / pull ──→  共享卷 /data/knowledge（本地 git 仓库）
                                                          ↑
                                                    文件读写（不走网络）
                                                          ↓
                                                    工作台 Pod（web-ui 进程）
```

1. **读**：工作台"工作台/决策中心"页面展示的信号/需求/设计，就是 web-ui 进程实时扫描
   `/data/knowledge` 下的 Markdown 文件（解析 frontmatter），**没有独立数据库**。
   知识库文件变了，页面刷新即见——这就是"改知识库不用重启"的原因。
2. **写**：唯一写入路径是平台操作（审核通过入库 / 归并 / 沉淀需求 / 改状态等），
   每次写入自动 `git commit` 到共享卷上的本地仓库（提交人信息带操作者账号）。
3. **与 gitlab 同步**：
   - 卷上的仓库 remote 指向 `wdp-team-knowledge.git`；
   - **初始化**（部署时一次）：`git clone` 知识库仓库到 /data/knowledge；
   - **⚠️ git 身份必配**（容易漏）：平台每次入库都执行 `git commit`，容器内**必须配置**
     `git config --global user.name "wdp-workbench" && git config --global user.email "workbench@wdp.local"`
     （写进 Dockerfile 或启动脚本）。没配的话 commit 会静默失败——**入库功能照常但丢失全部版本记录**，
     且页面只在返回信息里提示 "git commit 失败"，不易察觉。验收时务必 `git log` 确认有提交。
   - **日常出向**（卷 → gitlab）：入库自动 push（部署期与马冠杰确认启用；需 Pod 内 git 身份+token Secret），
     未启用时手动/定时 `git push` 亦可——不 push 只影响 gitlab 备份，不影响平台功能；
   - **日常入向**（gitlab → 卷）：管理员在本地改了知识库（如维护母版库）push 到 gitlab 后，
     在 Pod 里 `git pull` 即生效，不用动平台。
4. **两个仓库职责边界**：`wdp-team-platform` = 代码（改了要重新构建镜像）；
   `wdp-team-knowledge` = 数据（改了 push/pull 即生效，永不触发部署）。

## 三、部署步骤

### 1. 构建镜像
```bash
git clone http://gitlab.51cloud.local/Maguanjie/wdp-team-platform.git
cd wdp-team-platform
docker build -t wdp-team-webui:v1 .    # 细节见 BUILD.md
```

### 2. 准备 K8s 资源
按 `k8s/` 目录顺序应用：
```bash
kubectl apply -f k8s/pvc.yaml        # knowledge + profiles 两个 RWX PVC
kubectl apply -f k8s/secret.yaml     # 先从 secret.example 复制，填真实值（见下）
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl apply -f k8s/ingress.yaml    # TLS 证书 + sticky session 注解已配
```

**Secret 需要填的值（找马冠杰要）：**
- `OPENROUTER_API_KEY`：团队模型 Key（sk-or- 开头）
- gitlab 访问 token（知识库自动 push 用）

### 3. 初始化知识库卷
```bash
# 在能访问 PVC 的 Pod/节点上
bash scripts/init-knowledge.sh   # 或直接 git clone 知识库仓库到 /data/knowledge
```

### 4. 关键环境变量（deployment.yaml 已配，核对即可）

| 变量 | 值 | 说明 |
|---|---|---|
| HERMES_HOME | /data/hermes-home | 运行态根目录 |
| HERMES_KNOWLEDGE_DIR | /data/knowledge | 知识库目录 |
| HERMES_WEBUI_AGENT_DIR | /opt/hermes | agent 源码（镜像内） |
| HERMES_WEBUI_MULTIUSER | 1 | 多用户模式，必须 |
| WDP_SCHEDULER_ENABLED | 主 Pod=1，其余=0 | 定时任务单点执行，防多副本重复跑 |

### 5. 开通成员账号
```bash
bash scripts/add-user.sh <用户名>   # 幂等，自动建 profile 目录
```

## 四、必须注意的点

1. **sticky session 不能省**：对话是 SSE 长连接 + 服务端内存态，没有会话亲和会随机断流。
2. **Pod 需要公网出方向**：AI 分析（归并/审核助手）直连 `openrouter.ai`，出不去这些功能会报错（页面其它功能不受影响）。
3. **凭证纪律**：API Key、gitlab token 只走 K8s Secret，不进镜像、不进 git、不写配置文件明文。
4. **知识库是 git 仓库**：所有入库操作自动 git commit；自动 push 到 gitlab 需要在 Pod 配 git 身份 + token（部署时与马冠杰确认是否启用）。
5. **数据备份**：两个 PVC 是全部状态。knowledge 有 gitlab 兜底；hermes-home（成员账号/profile）建议每日快照。
6. **升级方式**：代码改动 → 重新构建镜像滚动更新；知识库/团队规则/技能改动 → git push 即生效，**不需要重启**。

## 五、部署后验收（跑完再交付）

1. 打开 https://<域名> → 出现登录页（绿白风格定制界面，非官方 Hermes 界面）
2. 用 admin 账号登录 → 左侧导航有：对话/工作台/决策中心/成员管理/团队 Agent/个人中心
3. 对话页发一句话 → 有流式回复
4. 工作台 → 信号列表有数据（初始化数据）
5. `kubectl exec` 进 Pod：`cd /data/knowledge && git log -1` 有提交记录
6. 详细验收清单见 `docs/公网部署-路由调整对比.md` 第四节

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 页面打开是官方英文界面 | HERMES_WEBUI_MULTIUSER 没设 / overlay 没打进镜像 |
| 登录后对话无响应 | 看 Pod 日志 agent dir 是否 [ok]；sticky session 是否生效 |
| 归并分析报错 | Pod 出方向访问 openrouter.ai 是否可达；Secret 里 Key 是否有效 |
| 成员登录互相挤下线 | 正常（单点登录设计），同一账号只能一处在线 |
| 工作库置灰"环境未登记" | 正常（设计如此），成员要在自己电脑的浏览器上登记设备 |
