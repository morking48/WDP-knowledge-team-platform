# 公网部署 · 功能路由调整对比（本地版 → 公网版）

> 更新：2026-07-23。给部署前的开发/运维对齐用：哪些行为在本地和公网不一样、要改什么。

## 一、总原则

平台代码不写死路径/地址，行为由**环境变量 + 配置文件**驱动。公网部署 = 换环境变量 + 补少量部署期动作，代码本体不改。

## 二、逐项对比

| # | 项目 | 本地开发版（现状） | 公网部署版（目标） | 改动位置 |
|---|------|------------------|------------------|---------|
| 1 | 入口地址 | http://127.0.0.1:8799，双击 bat 启动 | https://<域名>（Ingress TLS 终结）→ Service → WebUI Pod | k8s/ingress.yaml |
| 2 | 启动方式 | scripts/start-team-webui.bat（写死 E:\ 路径，**不上服务器**） | 容器 CMD 启动 server.py，环境变量由 deployment 注入 | Dockerfile / deployment.yaml |
| 3 | HERMES_HOME | E:\wdp-team-hermes\hermes-home | /data/hermes-home（PVC，RWX） | deployment.yaml env |
| 4 | HERMES_KNOWLEDGE_DIR | E:\wdp-team-hermes\knowledge | /data/knowledge（PVC，RWX，git 仓库） | deployment.yaml env |
| 5 | HERMES_WEBUI_AGENT_DIR | E:\wdp-team-hermes\agent-src | /opt/hermes（构建进镜像） | Dockerfile |
| 6 | 多用户开关 | HERMES_WEBUI_MULTIUSER=1 | 同左（必须保留） | deployment.yaml env |
| 7 | 会话亲和 | 无（单进程） | **sticky session 必配**（hermes_session cookie 亲和；SSE 长连接 + 内存态） | ingress.yaml annotation |
| 8 | 团队模型 Key | hermes-home/.env（本地真实 key） | K8s Secret 注入环境变量；.env 不进镜像不进 git | k8s/secret.yaml |
| 9 | 知识库写入 | 只 git commit 到本地仓库，**不 push** | commit 后**自动 push 到 gitlab**（需 Pod 内 git 身份+凭证 Secret） | review.py/knowledge_ops.py 加 push（部署期待办） |
| 10 | 知识库初始化 | 本地已有全量目录 | init-knowledge.sh 建初始结构 → **需对齐新结构**（library/ + knowledge.config.yaml + 各分区 _template） | scripts/init-knowledge.sh（部署期待办） |
| 11 | 定时任务调度 | web-ui 内置线程，本地默认关 | 多副本时仅主 Pod 设 WDP_SCHEDULER_ENABLED=1，其余 =0（防重复执行）；或改用 K8s CronJob | deployment.yaml env；见 docs/定时任务部署说明.md |
| 12 | 归并/审核 LLM 调用 | 服务器直连 openrouter.ai | 同左；**要求 Pod 有公网出方向访问**（或配 egress 代理） | 网络策略 |
| 13 | 个人工作库 | 成员/开发同机，machine_id 匹配即解锁 | 成员浏览器远程访问：服务器 machine_id ≠ 成员设备 → **登记/互锁行为不变，语义正确**（工作库本体永远在成员本机，服务器只存索引；agent 在服务器侧读不到成员本地盘属预期，提示成员上传或走 git 同步通道） | 无需改代码，需在用户说明里写清 |
| 14 | 成员 profile | hermes-home/profiles/<user>（本地盘） | 同结构落 PVC；add-user.sh 开通新成员 | scripts/add-user.sh |
| 15 | 团队规则发布 | admin 在「团队 Agent」页发布 → 写各 profile SOUL | 同左，机制不变（写的是 PVC 上的 profiles） | 无需改 |
| 16 | 认证 | 多用户 users.json + 单点登录 | 同左；建议叠加 Ingress 层 HTTPS + （可选）内网 IP 白名单 | ingress/网络策略 |
| 17 | skills 内绝对路径 | 部分 skill 文档写了 E:\ 示例路径 | 部署前统一改为相对/环境变量表述 | hermes-home/skills/（部署期待办） |

## 三、部署期待办（代码/脚本层，共 4 件）

1. **入库自动 push**：review.py `approve` 与 knowledge_ops.py 各写操作，在 git commit 后追加 `git push`（凭证走 K8s Secret 挂载的 credential helper，失败不阻塞入库、记日志）。
2. **init-knowledge.sh 对齐新结构**：library/{product-knowledge,archive}、knowledge.config.yaml、各分区 _template.md、README。
3. **skills 绝对路径清理**：`grep -rn '[A-Z]:\\\\wdp-team' hermes-home/skills/` 清零。
4. **submit_review.py 路径确认**：成员 agent 提交脚本按 HERMES_HOME 相对定位（已按此实现，部署后跑一次验证）。

## 四、部署后验收清单

- [ ] `GET /api/status`：hermes_home/config_path 指向 PVC 路径
- [ ] 登录 → 对话流式回复正常（验证 sticky session）
- [ ] 成员提交入库 → admin 决策中心可见 → 通过 → knowledge git log 新 commit **且 gitlab 远程可见**
- [ ] 归并分析真实返回分组（验证 Pod 出方向可达 openrouter）
- [ ] admin 团队 Agent 改规则 → 发布 → 成员端只读区同步
- [ ] 定时任务只在主 Pod 执行（开一个 1 分钟测试任务观察 last_run 不重复）
