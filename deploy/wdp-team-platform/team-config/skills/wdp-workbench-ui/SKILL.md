# WDP 团队工作台 UI 开发

> 为 WDP 产品团队多用户工作台（Hermes WebUI 二开）设计界面时的既定规范。视觉方向、交互铁律、文件归置均已与管理员（guanjie）逐轮确认——照此执行，不要另起风格或另选目录。

## 何时用
- 设计/修改工作台任何界面：登录页、工作台三组件（信息/需求/设计）、chat 对话页、个人中心、入库审核、成员管理
- 做 HTML 界面原型给团队评审
- 把确认后的原型接进 `web-ui/` 真实代码

## 视觉体系（已定稿，勿改方向）
- **配色：绿 + 白**。主色 `#16a34a`，强调渐变 `linear-gradient(145deg,#22c55e,#16a34a)`
- **iOS 液体玻璃**：`background:rgba(255,255,255,.6~.78)` + `backdrop-filter:blur(20px) saturate(160%)` + inset 白色高光边
- **淡网格背景**：28px 浅绿网格（两层 linear-gradient）+ 浅绿渐变底色，营造秩序感
- 圆角 18/12px；字体栈含 PingFang SC / Microsoft YaHei
- 起手直接复制 `templates/workbench-theme.css` 的 token 与基础样式

## 交互铁律
1. **可交互 vs 不可交互设计分化**（用户明确提出，最高优先级）：按钮必须有边框/hover/active 下沉反馈，一眼看出能点；纯展示元素（如用户角色卡）透明无框、`cursor:default`、`user-select:none`，角色身份用灰色小字而非带背景色标签。
2. **图标用简洁完整的 SVG**（stroke + 圆角线帽），避免超长复杂 path——曾出现设置齿轮绘制残缺被点名；设置图标用"圆 + 8 条放射线"这类简单结构。
3. **边栏 ~168px 展开式**（图标+中文标签+分组标题）：208px 被否（过宽），64px 纯图标被否（过空）。
4. **排版简练、功能切分干净不勾连**：导航按「工作（对话/工作台） / 管理（审核·成员，仅 admin） / 我的（个人中心）」分组。

## 工作流：mock 先行
1. **先做独立 HTML 原型**（纯前端 + mock 数据）→ 用户看效果提意见 → 改 → 确认后才接进 web-ui 真实代码。不要直接改主界面。
2. **原型文件放 `workbench/prototypes/`**——用户明确要求产出物归置到文件夹，严禁散落在 hermes-home/ 根目录。
3. **mock 数据贴 WDP 真实场景**（知识工坊/编辑器/麒麟OS/金仓/达梦/尊享版报价），含边界情况（待分配需求、停用成员、已归档、内部保密），同事才能提有效意见。
4. 给同事评审时保留**「视角预览」切换条（管理员/成员）**——权限视图差异是核心评审点。

## 组件交互模式（已确认，照做）
- **提示词模板 chips**（对话页底部）：点击→模板填入输入框；**无选中态**；输入框一旦有文字（或有待传文件）→ 全部 chips 置灰 disabled；清空恢复。skill 加载永远由 agent 按自然语言自动判断，chips 只是"递话"引导，不是硬触发按钮。
- **工作台可展开卡片**：信号表格行首 ▶ caret 点击展开详情（信号内容/关键信息 kv/原始信息摘录/管理操作）；需求看板卡点击就地展开（业务价值/溯源 sig 编号/目标版本/分配·通知按钮）。
- **模型渠道管理**：先配服务商+Key → 模型下拉随服务商联动 → 可配多个渠道 + ⚡测连通性 + 启用开关；对话页顶部下拉只列"已启用"渠道；一个都没配 → 显示"团队公共模型（兜底）"。
- **文件上传**：📎 按钮 + 整页拖拽（绿色虚线蒙层）；文件先落**个人工作库 uploads/**，不直接进团队 knowledge/；入库必须走"归档 → 管理员审核"。

## 个人/团队边界（架构级，勿越界）
- 个人工作库放**服务器** `profiles/<user>/workspace/`（不放各人办公电脑）——任何设备登录看到同一份；飞书/企微/TG 经 Gateway 接同一 profile。
- 个人中心四子页：我的 Agent（SOUL 风格 + 模型渠道）/ 个人工作库 / 个人 Memory / 运行日志——参照 WebUI 现有面板能力重组，不重复造轮子。
- 成员视角工作台只读；管理员多出管理操作 + 入库审核/成员管理两个专属 tab；写操作一律 git commit。
