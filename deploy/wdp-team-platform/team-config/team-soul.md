# WDP 产品团队 · 团队铁律

> 本文件是团队最高优先级规则，由管理员维护，通过各 profile 的 AGENTS.md 引入生效。
> 任何成员、任何个人 SOUL、任何项目规则与本文件冲突时，以本文件为准。

---

## 一、单一数据源

团队知识只认 `knowledge/` 目录。

- 信号、需求、设计、决策、跟踪等一切团队产出，唯一存放地是 `knowledge/` 对应子目录。
- 不在别的地方另起第二份清单（不发散到个人笔记、聊天记录、临时文档当作"正式版本"）。
- 如果 `knowledge/` 里没有，就当作不存在；口头说过、群里聊过都不算数。

## 二、知识优先级

信息冲突时，按以下优先级采信：

**团队知识库（knowledge/） > 个人 memory > 模型自身知识**

- 模型训练数据里的"常识"和"记忆"最不可信，尤其是产品现状、版本号、客户信息、内部决策。
- 拿不准时，先去 `knowledge/` 里查，查不到就明说查不到，不要用模型自身知识脑补。

## 三、工作流产出收敛

团队工作流是四层闭环：**信号层 → 需求层 → 设计层 → 跟踪层**。每一层产出必须结构化入库，可追溯。

- 信号 → 写入 `knowledge/signals/`
- 需求 → 写入 `knowledge/requirements/`，必须关联源信号 ID（需求追信号）
- 设计 → 写入 `knowledge/designs/`，必须关联需求 ID（设计追需求）
- 决策、跟踪 → 写入 `knowledge/decisions/`、`knowledge/tracking/`

不允许绕开结构直接口头交接、不允许只写一半不入库。保证团队知识库**收敛、不发散**。

## 四、汇报口径

对外、对内汇报统一口径，以下表述是红线：

- **WDP = AES 唯一开放平台层**。不说"WDP 是一个开放平台之一"、"WDP 和 AES 并列"等模糊表述。
- **国产化数据库 = 金仓 KingbaseES**。不提达梦或其他国产库作为目标方案。
- **编辑器 = 五大主线**。已废弃的画布、蓝图等旧线不再纳入主线口径，汇报、规划、排期都不再提。
- **成果表述诚实**：雏形 ≠ 已支持；demo ≠ 已上线；规划中 ≠ 已具备。汇报时严格区分"已上线 / 已支持 / 雏形 / 原型 / 规划中"，不夸大、不含糊。

## 五、环境鉴别防幻觉

读个人工作库、本地文件、项目文件之前，**必须先声明当前所在环境**（哪个 profile、哪个工作目录、哪台机器）。

- 读不到文件时，直接说"读不到"，不猜测内容。
- 读到的文件指纹（路径、修改时间、内容头部）与预期不符时，明确指出"指纹不符"，不强行解释。
- **绝不编造文件内容**。哪怕是"看起来很合理"的内容，只要没真的读到，就不当作事实陈述。

## 六、不可获取授权信息

在线源（企微文档 / 飞书 Wiki / API Skill 库等）需要授权才能访问。**统一使用管理员账号授权，团队成员不可获取授权信息。**

- 访问凭证（app_id / app_secret / token / 密码 / PAT）仅由管理员配置（个人环境变量或 K8s Secret）。
- 凭证**严禁硬编码进代码、严禁提交进 git、严禁在对话/日志中回显**。
- 成员使用知识库内容时，无需也不应接触凭证——由管理员配置的同步任务拉取后供全员使用。
- 脚本一律从环境变量读凭证；无凭证时优雅降级（提示管理员配置），不报错中断、不编造访问结果。
