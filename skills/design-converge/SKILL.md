# 设计收敛（Converge）——产品方案零歧义工作流

## 核心模型：掐两头，放中间
- **头部锁定意图**（高频交互）：批量拷问 → 补充调研 → 不可逆决策确认
- **尾部锁定交付标准**（低频确认）：验收方式 + 风险 + 成功指标
- **中间执行交给你自治**：意图锁定后不再反复打断用户
- **最终产物**：一份零开放歧义的完整方案文档，可提交入库为设计（designs），替代整段聊天记录成为唯一交付物

## 触发条件
- 用户开启「🎯 设计模式」（消息带 [设计模式] 前缀）——**强制走本流程，不许跳步**
- 用户明确说"帮我做方案收敛/用设计模式规划XX"

## 流程（8 步，按序执行，每步完成才进下一步）

### Step 0 · 开场
用户描述问题与约束。若描述过短（<30字），先请他补充：目标、背景、已知约束。**不要开始出题**直到有基本输入。

### Step 1 · ROUND 1 批量拷问（5-7 题）
**一次性输出 5-7 道选择题**（严禁挤牙膏式一问一答），覆盖：目标用户/核心场景/范围边界/优先级/依赖约束等。
每题用一个 ```choices 代码块输出（前端会渲染成可点击控件）：

```choices
{"qid":"Q1","question":"这个功能的目标用户是？","why":"决定交互复杂度和文档深度","multi":false,"options":[{"label":"团队内部成员","default":true},{"label":"外部客户"},{"label":"两者都要"}]}
```

格式规则：
- `qid`：Q1/Q2…顺序编号；`why`：一句话说明为什么问（可省）
- `multi`：true=多选；`options[].default`：true=推荐默认项（**每题尽量给默认**，用户可不答直接采纳）
- 块外正文只写一句引导："以下 N 题请点选或直接回复，带默认的不改即采纳。"
- 用户回复后，把「已锁定结论」清单化列出（✓ 问题→结论），再进下一步。

### Step 2 · DEEP RESEARCH（按需）
若有需要事实支撑的点（竞品做法/现有能力/历史设计），主动用工具调研：
- 查团队知识库：`python <团队scripts>/query_knowledge.py --find "关键词"`（看已有信号/需求/设计）
- 查产品知识：knowledge/library/product-knowledge/index.md 路由
- 外部检索：web 搜索
调研后输出 2-3 条关键发现（前缀「· 」），说明对方案的影响。没有需要调研的点可跳过，但要说明"本步无需调研，因为…"。

### Step 3 · ROUND 2 不可逆决策（2-3 题）
从方案中拎出**改了成本极高的决策**（技术选型/数据结构/对外承诺等），单独出题：
- 每题 choices 块中加 `"irrev":true`（前端会标红「不可逆·值得选」）
- **每个选项后必须给风险**：`options[].risk` 一句话（选了它最坏会怎样）
- 用户可回复"帮我研究 QX"，你就对该题做深入调研再给推荐

```choices
{"qid":"R1","question":"数据存储用哪种？","irrev":true,"multi":false,"options":[{"label":"沿用现有MySQL","default":true,"risk":"复杂查询性能瓶颈，后期迁移成本高"},{"label":"引入图数据库","risk":"运维成本+团队学习曲线，短期交付变慢"}]}
```

同时列出「已判定可逆、下放执行不再问」的项（如按钮文案、内部命名），明确告知用户这些你会自行决定。

### Step 4 · 闸门 1：意图锁定
汇总**全部已锁定结论**（清单：✓ 问题 → 结论 → 来源[用户选/默认采纳]），问用户："意图已收敛，还有 N 个开放点（如有则列出）。确认锁定进入交付标准，还是要调整？"
**用户确认前不进 Step 5。**

### Step 5 · 交付标准（轻量，产品视角）
一次性问 3-4 题（同 choices 格式）：
- Reality Check：这个方案最可能失败的点是什么（给选项）
- 验收方式：怎么算做完（演示可用/试点跑通/正式上线指标）
- 成功指标（North Star）：1-2 个可验证的指标

### Step 6 · 闸门 2：标准确认
列出交付标准结论，用户确认后进产物。

### Step 7 · 产物：完整方案文档
输出结构化方案文档（markdown），固定 7 节：
1. **背景与目标**（开场输入提炼）
2. **已锁定意图**（Round1 全部结论）
3. **关键决策与风险**（Round2 不可逆决策+选择理由+接受的风险）
4. **调研依据**（Deep Research 发现）
5. **方案主体**（基于以上收敛结果展开的具体方案——这是你自治发挥的部分，要具体可执行）
6. **交付标准**（验收方式+成功指标）
7. **已下放的可逆决策**（执行时自行决定的项）

文档末尾问："方案已零歧义。要提交入库为设计稿（designs）吗？"用户同意则走 submit_review.py 提交（category=designs，流程见团队规则）。

## 纪律（硬约束）
1. **批量出题**：每轮一次性出完，严禁一问一答挤牙膏。
2. **每题给默认**：让用户"不答也能走"，降低负担；默认采纳的在结论里标注「默认采纳」。
3. **不可逆必标风险**：Round 2 每个选项都要有 risk。
4. **闸门必须停**：Step 4/6 必须等用户确认，不许自行冲过闸门。
5. **choices 块格式严格**：合法 JSON、双引号、无注释——前端要解析渲染成控件，格式错控件就废了。
6. **产物自包含**：最终文档不依赖聊天记录也能看懂、能执行。

## 避坑
- 用户中途跑题问别的：简短回答后拉回流程（"回到收敛流程，当前在 Step X"）。
- 用户想跳步（"直接给我方案"）：提醒一次风险（歧义未收敛，方案可能返工），他坚持就跳，但产物文档里标注「未经完整收敛，以下假设未确认：…」。
- choices 块内容含中文引号/换行要转义，保持 JSON 合法。
